# yumegaoka — MVP要件定義書 v0.14（現行仕様）

更新：2026-10-29。会話の最新の合意を統合。過去案は [履歴](history/MVP_REQUIREMENTS_BEFORE_CONSOLIDATION.md)、根拠は [DECISIONS.md](DECISIONS.md) に保存。未決定事項を実装仕様に自動昇格させない。

## 1. 目的・段階

**街の人の気配を感じることができる、孤独な人間のための第六感。**

何も投稿しなくても人の存在を感じ、会話・合流・人間関係の維持を義務にしない。街に参加することと特定の相手を募集することを分ける。文化が現実に成立することが最終目的。

初期顧客は招待された通話界隈の人々、池袋でのオフ会を起点とする。当面はiPhone向け。Androidへの将来移植は必要だが、現在の設計・実装・検証・公開条件には含めない。所有者が運営する。定性的な観察は仮説として扱い、追加インタビューを開発の先行条件にしない。

現在は中核フローを部分実装・部分検証済み。2026-10-30にMVP全体の監査と実行計画へ切り替えた。全体進捗は[MVP_TASKS](MVP_TASKS.md)。今回は文書整備までで停止し、次の指示で全画面・全機能の実装を再開する。契約・購入・公開は別判断。

## 2. 参加・アカウント

- 招待登録済みの利用者のみ街の人数・地図・チャット・ピンを閲覧できる。招待案内画面は公開可能。
- 参加者も友人を招待でき、運営が状況を監督・無効化できる。
- サーバーにアカウント情報を保存。新端末から同じアカウントへログインして引き継ぐ。QR引き継ぎは不要。
- Supabase Authのメール確認コード（OTP）方式を採用。招待リンク→メール入力・コード認証→名前とアイコン設定→利用開始。普段はログイン状態を維持し、機種変更時も同じメールでログインする。
- メール認証と招待による利用資格は別。初回は有効な招待が必要で、メール認証だけでは街情報へアクセスできない。既存の有資格アカウントの再ログインに新しい招待は要求しない。
- メール変更は現在認証と新旧メール確認を要求。メール紛失時の自動復旧はMVP対象外。退会は再認証後に資格停止・滞在終了・プロフィール削除・投稿匿名化し、既存保存期限は維持する（M04）。通常ログインでは旧端末も維持する。滞在更新元の自動移行はしない。退会時は未使用招待を無効化し、投稿制限/招待枠設定/本人宛通知/配信待ちを削除する。本番コード期限・試行制限・送信基盤等は本番運用時に決める。
- アカウント設定で名前・本人アイコンを設定する。
- ヘッダーの画像列は現在有効な気配に割り当てた街pool画像を表示幅とアイコン寸法から算出した個数と残り人数で表示する。チェックイン人数は別表示とし、10分の気配と3時間の滞在人数を混同しない（2026-10-31承認）。
- チャットは本人の名前・本人アイコン。地図の気配は流動的な街アイコン。アカウント登録時に利用者が街poolへ提供する画像をアップロードし、街に保存する。地図で自分に表示されるアイコンはpoolから選び、1日ごとにランダムにシャッフルする（2026-10-30訂正）。登録UIで共有用途とシャッフルを説明する。チャット用の本人画像とは別に設定する。当日の割当画像を本人が確認でき、地図にも同じ画像を表示する。日本時間午前0時に日替わりする。提供者による差し替え・削除と退会時にはpoolから取り下げる。名前や個人IDを気配APIに公開しない。未公開の準備画像は準備開始から24時間で削除対象とし、期限後の読取・アップロード・公開を拒否する。期限切れ後は画像選択からやり直せる。公開済み画像と登録完了状態はこの期限で消さない。実装・検証状況はMVP_TASKSを参照。

## 3. 街へのイン・アウト

- 新規チェックインは毎回NFC必須。終了・失効後に位置確認だけで再参加しない。
- NFC読取後の開始試行はサーバー発行から2分以内に確定し、超えたら再タッチ。処理済みの結果照会は可能。
- 位置権限拒否時は新規チェックイン不可。権限があり一時的に測位不能なら滞在だけ開始し、初回観測まで気配を作らない。閲覧・チャットは継続可能。
- 右上トグルのOFF→ON操作でNFC読み取り。サーバー登録成功後にON確定。キャンセル・失敗時はOFF。
- 有効期間は3時間。新しい街内観測による気配更新成功時はサーバー受理時刻から3時間へ延長する。前面復帰時にも位置を確認する。
- トークン一致だけでは足りず、滞在が有効・未退出・期限内であることと観測の鮮度・順序を検証する。
- OFFで手動退出。観測・更新を止め、気配と募集ピンも終了。退出後も街の閲覧・チャットは可能。
- 通信不能時は端末の退出意思を保持して延長を止め、再接続時に終了通知。サーバー反映は即時保証できず、各期限が上限となる。
- 更新不能なら気配は10分、チェックインは3時間で失効。位置不明は街外と断定しない。明確な街外では退出する。
- 一つの滞在を更新する端末は一つに限定する。別端末で同じアカウントにログインしても、その滞在の更新権限を自動移行しない。更新元は検証済みAuthセッションIDに結び付ける。通常のトークン更新は継続できるが、ログインし直してセッションが変われば同じiPhoneでも再NFCが必要。物理端末の真正性を保証する方式ではない。再NFC時は下記の例外処理に従う。
- 遅延要求・再送・同時処理で人数を増殖させたり、終了済み滞在を復活させたりしない。複数端末による意図的な水増し対策はMVP対象外。


### 入退場の例外処理（2026-10-29承認）

- 入街処理中のキャンセルは入街を取り消す。すでにサーバーで成立していれば、その滞在を終了する。通信断では反映待ちとし、古い成功応答で再参加させない。
- 同じ端末のNFC再タッチ時に対象街の有効滞在があれば、既存状態を返し人数・入街ログを増やさない。再タッチだけでは期限を延長しない。
- 別端末で新しくNFCにタッチした場合は、同じアカウントの旧滞在を終了し、新端末の新しい滞在を開始する。旧気配・旧募集も終了し、旧端末の遅延更新は拒否する。ログインだけでは切り替えない。
- ログアウトは、その端末が更新している滞在を終了する。他端末の滞在を巻き込まない。通信断なら端末の観測・更新を止め、サーバー側は既存期限で失効する。ログアウト後の終了通知の認可・送信手順は詳細設計。
- 運営の利用停止では滞在・気配・募集も終了し、開催前・開催中の主催イベントを自動中止して参加者へ通知する（M06）。解除でイベントも復活させない。一般参加者としての参加登録も自動取消し、解除で復活させない。解除だけでは再参加させず再NFCを要求。投稿だけの制限では滞在を維持する。

## 4. 街の気配（MVPの核）

- 入口だけでなく、街で移動した先にも気配が生まれる。投稿・募集操作は前提にしない。
- 画面を閉じてポケットに入れたままの移動にも対応する必要がある。OS都合の欠測は許容し、古い観測は10分で消す。電池効率は未確認。
- 静止中の更新方針は距離フィルターを外し、新しい測位の際、区画移動または同一区画で前回送信から約3分経過なら更新する。古い座標を定刻で再送しない。本体Swiftモジュールには反映済み。旧試作は保持しており、本体での実機静止・背景通信確認は残る。
- 気配は10分で透明度が下がり消える。移動前の痕跡を積み上げず、同一滞在の最新1件を置換する方針。具体APIはFIRST_SLICE_CONTRACT、更新元認証はL01を参照する。
- 地図に人数を表示。6人までは一つ、7人は5＋2に表示分割する。観測位置を変えず周囲へ描画上だけずらす。8人以上は残りが6人以下になるまで5人ずつ分ける（8→5＋3、11→5＋6、12→5＋5＋2）。
- 他利用者に名前や追跡用の安定した個人キーを公開しない方向。サーバー内で滞在・アカウントと対応付け得るため、完全匿名を保証しない。
- 正確な個人位置の常時公開や移動履歴の保存は目的としない。気配は端末で街内判定・区画化して区画IDを送るA案を採用。気配更新で生座標はサーバーへ送らない。区画は100m四方を採用。公開集約は区画別人数と失効予定を端末へ返す方式を採用。個人IDは渡さず、各気配を期限どおりフェード・消去する。時刻相関による人物推測への追加対策はMVP後に再検討する。サーバーは滞在の資格・期限・順序・区画の妥当性を検証するが、端末の位置申告の真偽を独立には保証できない。
- 入街前に背景で気配を共有することを説明する。停止はトグルOFF。
- 観測が途切れて気配が消えたことは現地0人の証拠ではない。架空の人を追加して賑わいを作らない。

### 観測の受理条件（2026-10-29承認）

初期設定として採用。最適値・省電力性が実証済みという意味ではない。

| 項目 | 承認済み条件 |
| --- | --- |
| 区画 | 100m × 100mの固定区画。正確な合流地点は募集ピンで扱う |
| 測位精度 | 推定水平誤差50m以内の有効な測位を採用。精度不足は更新保留 |
| 鮮度 | 観測からサーバー受理まで120秒以内、かつ前回受理した観測より新しい |
| 移動時 | 区画変更時に送信。ただし最短30秒間隔 |
| 静止時 | 同一区画で前回送信から約3分経過後に得られた新しい観測を送信。古い位置の定期再送は禁止 |
| 初回 | 有効な観測が取れたら即送信。3分待たない |
| 区画境界 | 隣の区画へ20m以上入った観測で表示先を切替。それまでは元の区画を維持 |
| 街外周 | 測位誤差を考慮して内外不明なら更新・自動退出とも保留。明確な街外観測が30秒以上・最大120秒の間隔で2回続いたら自動退出 |

保留中は気配・滞在の期限を延長せず、既存の10分／3時間で失効する。手動退出は街外の2回確認を待たない。街内判定と区画切替の判定を混同しない。距離フィルターなしの方針を維持し、測位頻度と送信頻度は分ける。OSが定刻に測位を届ける保証ではない。

外周のNFC設置地点では内外判定を保留し、滞在人数には入っても初回気配が出ない場合がある。タグ位置で気配を作ったり、無断で街範囲を拡張したりしない。推定誤差は確実な包含範囲ではなく、100m区画も匿名性を保証しない。

時計補正・許容未来幅、固定区画の原点／座標系、角や飛び越し時の20m判定、街外確認の中断・再起動時の扱いは具体設計として残る。

## 5. 街・ステッカー・地図

- 初期設置は3か所以上。登録位置の凸包を街の外周とする。直線・地点不足等は検証し、範囲プレビュー後に確定する。
- 移設・交換・撤去に対応。タグの識別情報と最新設置位置を分け、旧タグ無効化・範囲の版管理を行う方向。
- 範囲変更だけで既存参加者を一斉退出させず、次回観測に最新範囲を適用する。
- NFCに前の利用者名を書かない。タグには識別情報を置く。運営端末で基本設定を書き込む。運営の書き込み端末はiPhone。
- ステッカーは書込み・再読取照合・現地設置確認後、街の範囲をプレビューして公開する。初回3枚以上を準備し範囲と一括公開。未確認のタグは有効化しない。
- タグには識別IDと書式版を記録し、場所と街はサーバーで管理。移設時は一時停止・新地点の読取と位置確認・範囲プレビュー・再公開。移設だけならタグ内容の書換えは不要。
- 地点不足・一直線等で有効な新範囲を作れないときは旧範囲を一時保持し、代替地点を用意する。タグ停止自体は可能とし、範囲未更新を運営へ明示。初回で旧範囲がなければ受付を開始しない。
- 地図は当面MapLibre React Native。高品質な独自3D表現は「夢ヶ丘エリア」の文化的合意が生まれてから検討する。
- タグ機種・保護方式・地図タイル提供元は未決定。境界計算はOBSERVATION_RULES、実装・検証範囲はMVP_IMPLEMENTATION_AUDITを参照する。

## 6. 募集とオフ会

### 募集ピン

- 有効チェックイン中のみ作成。現在地を単発取得し、公開位置を確認して題名を付ける。
- 同時1件、20分で終了。手動終了・チェックアウト・滞在失効でも終了する。
- 題名は編集可。位置変更・継続は終了して再作成。編集で期限を延ばさず、終了したピンを復活させない。
- 公開後の位置は追従しない。気配とは別の、合流を求める意思表示。

### オフ会・イベント管理

- 未チェックインでも事前作成可能。題名・開始終了日時・場所が必須、説明は任意。
- 作成シート→地図で地点選択→入力を保持したシートへ戻る→公開。
- 開催前は開始まで、開催中は終了までを表示し、終了後マップから消す。時間表記の詳細は画面設計。
- ピンをタップすると詳細シート。「参加する」で参加登録し、Homeの参加予定へ表示。開催中も空きがあれば参加可能。終了・中止後は新規参加不可。参加取消は終了まで可能で、空いた席は再募集できる。
- 初期範囲：作成・編集・中止・参加・参加取消・定員・主催者の参加者一覧・重要変更連絡。
- 日時・場所変更と中止はアプリ内通知＋プッシュで連絡。通知拒否時もアプリ内で確認可能。題名・説明のみの変更では毎回プッシュしない。
- 主催者による個別の参加取消（除名）はMVPに入れず、問題は運営への通報で対応。
- 中止したイベントは参加予定一覧から外し、中止通知は中止後24時間以内だけ保持、その後参加者との対応を削除。未閲覧・プッシュ不達では連絡を見逃す可能性を許容する。
- 参加者名は主催者・運営のみ、一般参加者には人数のみ。本人は自分の状態を確認できる。
- 参加登録と街のチェックインは別。参加操作で街人数を増やさない。
- 定員を参加済み人数より少なく変更できない。終了・中止したイベントは再開せず、新しいイベントとして作成する。
- 遅延した参加要求で取消を復活させないため、イベントが有効な間は取消済み登録の最小状態を保持する。
- 過去の参加履歴は表示しない。終了後24時間以内に参加登録情報を削除する。通報証拠は既存の別管理ルールに従う。中止時は中止時点から24時間以内に参加登録を削除する。中止連絡もこの保存期限に合わせる。通知先の削除と再試行の具体方式は詳細設計。
- 承認制・待機列・当日受付・決済はMVP対象外。

## 7. チャット・画面・運営

- 街ローカルのテキストチャット。未チェックインでも閲覧・投稿可。名前・投稿日時・本文・本人アイコン。
- 名前付きの入街ログで友人の来訪を知れる。入街ログは通常チャット同様30日表示、その後24時間以内に削除。気配との時刻相関から本人が推測される可能性は残る。
- 遡る操作で過去30日分をロード。本人・運営による削除、通報、投稿制限、個人ブロックを扱う。運営は他人の本文を書き換えない。
- チャットを上へ広げて背景をぼかす。ジェスチャー・キーボード・閉じる動作は画面設計で確定。
- Homeは参加予定・未参加の「街のイベント」・募集中のピン一覧（2026-11-05追加）。参加予定は本人の参加登録済みイベント、街のイベントは未参加の未終了イベント、募集中は有効な募集ピン。更新はpull操作とし、Homeに専用リロードボタンは置かない。Mapは街の気配・募集・オフ会・チャット、Settingsはアカウント関連。
- 現在地へ戻る操作と位置公開は別。最初に開くタブはMap（M01）。2026-11-02のタブ構成はHome／Map＋街チャット／お知らせ／Settings。人数は街名の隣、API雲ロゴは表示しない。
- チャットはドラッグ中だけ拡大し、指を離すと縮小。履歴をリセットしない。Mapの新規パネルはsmoothing 60%。具体対応は[MAP_REDESIGN](frontend-redesign/MAP_REDESIGN.md)。
- ゴースト（人数維持・自身の気配非表示・募集終了）、現在滞在時間レベル、メンションのお知らせ/Push、募集者の当日pool画像、3D背景は追加要望として後工程で詳細化する。今回のUI変更で実装済みとは扱わず、既存の退出・更新仕様を変更しない。
- 運営が招待監督、通報確認、投稿削除・一時停止・利用停止・解除、ステッカー登録・書き込み等を行う。運営はメールOTPに加えてTOTP/MFAを必須とし、サーバーが運営資格と追加認証を毎回確認する（M03）。
- 削除した投稿は本文を消去して「削除されたメッセージ」と表示。最小の削除状態は元の履歴期限まで保持し、通報証拠は別管理。
- ブロックは自分の画面から対象のチャット・入街ログ・募集を非表示にする。匿名の気配・街人数は減らさず、イベントは自動非表示にしない。相手から自分を隠す機能ではない。
- 権限検証・入力制限はサーバー側で行う。通報数だけで永久停止しない。

## 8. 承認済みの初期上限

| 項目 | 初期値 |
| --- | --- |
| 招待 | 1コード1回、7日有効、7日間に5件発行／参加者。運営が追加・停止可能 |
| チャット | 500文字、10秒に5件かつ1分に20件／人 |
| 履歴 | 1回50件、10秒に5回／アカウント |
| 募集 | 同時1件 |
| ピン作成 | 1分に3件／人、取消・再作成も含む |
| オフ会 | 同時3件、開始90日先まで、開催期間24時間以内 |
| 題名・説明 | 50文字・1,000文字 |
| 接続 | 1端末原則1本、1アカウント3本。再接続の一時重複は許容 |

## 9. 保存方針

- チャットは30日超で取得対象外、その後24時間以内に削除。
- 終了したピンの本文・座標は取得対象外とし、24時間以内に削除。通報対象の最小証拠は別管理。
- 開始試行の最小記録は受付期限後24時間で削除。
- 終了滞在の再送判定用最小情報は24時間後に削除。削除済み滞在の要求を新規参加と扱わない。
- 気配の公開は10分。生座標・移動履歴を蓄積しない方向。退出時は同じ終了処理で気配を削除。自然失効では即非公開、失効後1時間以内にライブDBから削除。WAL・バックアップの即時消去保証とは別。
- 通報証拠は運営限定、対応完了後30日で削除。未対応90日で整理。未対応通報は最長180日で削除（M05）。
- セキュリティログ原則7日、運営操作記録90日。本文・位置・秘密トークンをログへ出さない。
- バックアップ原則7日を選定条件とし、実現可能性を確認。復元時は期限・削除・停止を再適用。
- 招待関係は有効アカウントの監督に使用。イベント参加登録は終了後24時間以内に削除。中止時は中止時点から24時間以内に削除。退会はM04に従い匿名化し、保存期限を延長しない。未完了ステッカー下書きは最終更新から7日で削除（M05）。
