## 差替え時に守る前提

- UIのmount/unmountをログイン・入街・退会・投稿の意思として扱わない。副作用は対応操作と状態機械へ渡す。
- 入街/退出/観測の永続状態・時計補正・100m区画化・境界判定はnative/DBに保持する。端末が取得した精密座標の継続送信を追加しない。
- 1滞在の更新元は1端末。本人が新たにNFCで入街した時だけ切替。退出済/失効済は背景更新で復活させない。
- 画面の成功表示はAPI結果と状態確認に基づく。送信中・通信不明・失効・認可拒否を区別し、通信失敗を成功へ変換しない。
- 操作受付/revision/再送識別子を画面再描画ごとに再生成しない。削除/停止/取消し後の復活を防ぐ既存API契約を維持する。
- 通常閲覧は街外でも可能。募集公開の現地条件と閲覧/チャット権限を混ぜない。
- 公開マップは流動的な街アイコン、チャットは本人名/本人アイコン。気配が薄くなることは「街に誰もいない」の証明ではない。
- ブロック/通報/停止と通知保持を見た目だけで実装しない。サーバー認可をUIの非表示で代替しない。
- 背景観測の実行時刻はiOS次第。権限/省電力/強制終了の制約はT010/T032で実機確認が必要。NFC/Pushの実機確認はADP等の外部依存を分離。

## 残る分離と確認

今回触れたMemberRowはAPI/検証をhookへ分離済み。他画面の総入替えや一律リファクタリングはしない。上表でappを直接参照する箇所は、実際のFigma差替えで必要になった操作境界だけ追加分離する。ロジックの認可・期限・再送試験を再利用し、画面変更に関連する操作を確認する。現行UIの仮操作証拠はNAVIGATION_ACCEPTANCE/LOCAL_FLOW_ACCEPTANCE、ロジック段階はLOGIC_PROGRESSを参照。
