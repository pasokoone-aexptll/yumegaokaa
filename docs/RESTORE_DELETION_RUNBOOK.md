# 復元時の削除情報の再公開防止（運用案）

2026-11-25。R17/R18。既存FIELD_BACKUPの隔離復元に追加する手順。今回復元試験は実施しておらず、この文書だけで公開適合済みとはしない。

1. バックアップは別の非公開DB・Storageへ復元する。復元したAuth・配信worker・外部からのアプリ接続を本番へ直結しない。
2. 復元世代作成後の退会・削除・通報対応を照合する。現在DBが利用できる場合はその削除状態を優先し、削除済み画像を復元公開しない。
3. 最新のmigrationを適用し、期限清掃と対象の削除を隔離環境で実施する。Auth・メール・通知・画像参照も確認する。
4. 現在DB喪失などで世代作成後の削除を照合できない場合は公開を再開しない。外部の削除台帳など、正しい削除状態を再構成できる方法を先に確立する。
5. 退会済みアカウントでログイン・公開画像・投稿取得ができないことを確認し、確認者・日時・世代・対象範囲を内部記録してから切り替える。

未決定：DBから独立した削除台帳の最小情報・保存期間・保存先。長期保持を独断で追加しない。台帳には本文・画像・位置・メールを含めない案を基本とするが、設計と保持判断は別途必要。
