## 2. 目的・対象・範囲

### 2.1 目的

現実の街で他者の存在を感じ、特定の人間関係を維持する義務を負わず、参加・退出できる空間を作る。アプリ普及自体ではなく、現実の「夢ヶ丘」という文化の成立を目指す。

MVPは通話界隈のオフ会で利用し始める。オフ会ピンが集合のきっかけを作り、人数・チャットが街の様子を伝え、募集ピンが現地での合流を支える。

### 2.2 対象

- 初期利用者：招待された通話界隈の人々。
- 初期実験場所：池袋を想定。
- 利用者アプリ：iOS・Android。
- 運営：プロジェクト所有者。運営用クライアントも必要。
- リリース順序、試験人数、対応OSバージョン、運営クライアントの形態は未決定。

### 2.3 MVPの構成

中心機能は街へのイン／アウト、街ローカルチャット、ピン、街の様子を表示するマップ。これを支える招待・アカウント・ログインによる引き継ぎ・通報／制限・運営機能を含む。

リアルタイムで個人の位置を追い続ける共有機能は不要。人数は正確な実在人数ではなく、有効なチェックイン数による賑わいの目安。複数端末による人数水増し対策はMVPで考慮しない。

DM、フレンド、通知等は過去の候補であり、MVPに採用されたとは扱わない。独自の高品質3D街モデルは、文化の中で夢ヶ丘エリアの合意が生まれてから検討する。当面はMapLibre React Nativeを使う方針。画像中の文字・API名・人物表示は新たな要件の根拠にしない。

## 3. 利用者と権限

| 操作 | 未チェックインの参加者 | チェックイン中の参加者 | 運営 |
| --- | --- | --- | --- |
| 人数・地図・ピン・チャット閲覧 | 可 | 可 | 可 |
| チャット投稿 | 可 | 可 | 可 |
| オフ会ピン作成 | 可（事前予約用途） | 可 | 可 |
| 現在地の募集ピン作成 | 不可 | 可 | 通常の募集は同じ条件 |
| 自分のピンの編集・取消・募集終了 | 可 | 可 | 可 |
| 他者の投稿の削除・利用制限 | 不可 | 不可 | 可 |
| 招待発行 | 可、上限あり | 可、上限あり | 監督可能 |
| ステッカー設置位置・街範囲の管理 | 不可 | 不可 | 可 |

「参加者」は招待を経て利用資格を得た人を指す。街へのチェックインとアカウントへの認証を区別する。停止・制限中は制限内容を優先する。街の内容は招待登録済みの利用者に限定する。未招待者・未認証者には招待案内のみ公開する。運営は他者の本文を書き換えず、削除・制限で対応する。

## 5. チェックイン・更新・退出

| ID | 要件 |
| --- | --- |
| PRE-01 | 新しいチェックインを開始する際は、毎回現地のNFCタッチを必要とする。過去にタッチした事実だけで自動参加させない。 |
| PRE-02 | チェックインは3時間で失効する。更新がなければ端末からの通知がなくても人数から外れる。 |
| PRE-03 | 有効なチェックイン中にアプリを開いたとき、位置を取得し、まだ街にいるか端末内で判定して更新する。確認用の座標はサーバーへ送らない。 |
| PRE-04 | 更新によって有効期間を3時間延長する。更新による人数の追加は行わない。期限はサーバーが延長を受理した時刻から3時間とする。 |
| PRE-05 | 右上の入退出トグルをOFFにして手動退出できる。終了後の再参加はNFC必須。期限切れ後も位置確認だけで復帰しない。 |
| PRE-06 | 退出後も人数・ピン・チャットの閲覧とチャット投稿が可能。アプリを開くだけで再参加しない。 |
| PRE-07 | 遅延・再送された更新で終了済みのチェックインを復活させず、通信再送等による意図しない人数の重複を防ぐ。 |
| PRE-08 | 表示する人数は有効なチェックイン件数。個人の参加者一覧や位置追跡を必須としない。気配は別の10分の痕跡として方式を設計中。 |

状態の整理：

| 現在の状態 | 出来事 | 結果 |
| --- | --- | --- |
| 未参加・退出済み・失効済み | NFCから新規チェックイン成功 | 有効になる |
| 有効 | 街内と確認でき、更新成功 | 有効期間を更新、人数は同じ |
| 有効 | 手動退出成功 | 終了し、人数から外れる |
| 有効 | 有効期限に到達 | 失効し、人数から外れる |
| 終了・失効 | 位置確認・遅れて届いた更新 | 復帰しない |

バックグラウンド更新と定期測位はMVP対象外。明確な圏外では退出し、位置取得拒否・低精度・通信失敗等では延長せず既存期限を維持する。オフラインの手動退出では端末に退出意思を記録して更新を止め、再接続時に終了を送る。アプリを閉じたまま／開いたままで3時間更新されなければ失効し、再NFCが必要。通常の固定NFCデータだけでは現地性を厳密に証明できない点を理解して対策範囲を決める。

| GEO-02 | 外側のステッカー位置を結んだ多角形の内側を街の範囲とする。外周算出は凸包を初期方式とする。 |

ステッカー識別と位置の分離、移設・撤去・交換、設置点不足・一直線の検証、境界の測位誤差を考慮すること、変更のプレビュー・版付き一括確定はP04として承認済み。境界の許容幅は実地で決める。運営端末でのNFC基本設定の書き込みも必須。書式・タグ機種・保護方式・失敗時の処理は設計する。

## 7. ピン・チャット・街の表示

### 7.1 ピン

| ID | 要件 |
| --- | --- |
| PIN-01 | 参加者は共有マップ上にピンを作成できる。オフ会ピンと募集ピンを区別する。 |
| PIN-02 | オフ会ピンはマップで地点を選び、題名・開催日時を設定して事前作成できる。吹き出しに題名と開始までのカウントダウンを表示する。 |
| PIN-03 | オフ会ピンは指定した終了日時で表示を終了する。 |
| PIN-04 | 募集ピンは有効なチェックイン中に、単発で取得した現在地と題名を公開する。公開後の移動を追跡しない。 |
| PIN-05 | 募集ピンは原則20分で終了する。継続する場合は新しく作成する。 |
| PIN-06 | ピンの編集・取消・募集終了ができる。募集ピンは手動終了・時間切れ・チェックアウトで終了する。チェックイン失効も終了に含む。 |
| PIN-07 | 作成頻度と同時掲載数を制限する。本人の操作権限を検証する。具体値は未決定。 |

公開終了と物理削除を区別し、終了したピンの本文・座標は24時間以内に削除する（通報証拠は別管理）。募集は公開位置を確認してから作成し、座標は追従しない。題名のみ編集でき、位置変更は再作成する。終了済みピンを編集で復活させない。オフ会説明は任意、開始後は「開催中」とする。

### 7.2 街ローカルチャット

| ID | 要件 |
| --- | --- |
| CHAT-01 | 街ごとのチャットを持ち、名前・アイコン・テキストをライブチャットのように表示する。 |
| CHAT-02 | チェックインしていなくても閲覧・投稿できる。発言の存在を現地滞在の証明と扱わない。 |
| CHAT-03 | 新着を速やかに表示し、遡る操作で過去30日の履歴を追加読み込みする。速度の数値目標は未決定。 |
| CHAT-04 | 削除・通報・投稿制限を設ける。運営による削除・一時停止・利用停止と解除を扱う。 |
| CHAT-05 | 連投・文字数・取得量・接続数等を制限する。重複通報を抑え、通報件数だけで永久停止しない。 |

P05〜P07により本人・運営による削除、テキストのみ、1回50件、再接続時の欠落補完・重複抑制、通報証拠の基本保持方針を採用する。個人ブロックを含める方向で、具体的な非表示対象と削除後の表示は未決定。

### 7.3 UIと画面の構成

合意済みの要素：街の地図・人数・チャット・ピン、入退出トグル、アカウントタブ、全画面でのピン位置選択、募集／オフ会タブ付きの追加シート。

NFC処理中・成功の独自アニメーションを希望。iOSの通常のCore NFCでは読み取り中に標準シートが出るため、独自表示は読み取り完了後のサーバー登録段階に置く案。通信成功前に完了を表示しない。

画面一覧の整理案：招待／登録、街ホーム、全画面ピン位置選択、ピン作成・詳細・編集、アカウント／引き継ぎ、通報、運営。ナビゲーションや細部は未承認。

## 9. 主要ユーザーフロー

1. **参加と予定**：招待を受ける → アカウントを設定 → 街の様子を見る → オフ会ピンを作る／予定を確認する。
2. **現地参加**：NFCを読む → チェックイン成功 → 人数へ反映 → 街の中で過ごす。
3. **募集と合流**：有効チェックイン中に募集を作る → 現在地を公開 → 他の参加者が地図で確認 → 手動終了または20分で終了。
4. **継続と退出**：有効期間内にアプリを開いて街内を確認 → 期限更新。手動退出または失効 → 募集も終了。再参加はNFCから。
5. **端末引き継ぎ**：新しい端末で同じアカウントへログイン → サーバーのプロフィール等を取得。旧端末での承認・QR操作は不要。
6. **運営**：通報・招待状況を確認 → 必要な措置。設置点を変更 → 街の範囲を更新 → 次の位置確認から最新範囲を利用。

### 12.2 保持・削除（P07承認）

- チャット：30日超で取得対象外、物理削除はその後24時間以内。
- ピン本文・座標：終了後取得対象外、24時間以内に削除。通報対象の最小証拠は別管理。
- 終了した滞在：再送判定用の最小情報を24時間後に削除。削除済みの更新要求から新規参加を作らない。
- 通報証拠：運営限定、対応完了後30日で削除。未対応90日で整理を要求。未対応の最長保持期間は未決定。
- セキュリティログ：原則7日。本文・位置・認証トークンを記録しない。
- 運営操作記録：90日。本文を複製せず操作内容を記録。
- バックアップ：原則7日を選定条件とする。サービスの実現可否と最大残存期間を検証する。復元後は期限・削除・停止状態を再適用する。
- 招待関係：アカウント有効中は保持。退会後の期間は未決定。
- アカウント削除も設計に含める。退会後の投稿・通報・制限情報の残し方は明示して決める。

## 最新の追加合意

地図は流動的な街アイコン、チャットは本人名・本人アイコンに分離。NFCは名前の書き込みを避け識別情報を使う。移動先でも気配が生まれることが必須であり、入口の一回の痕跡のみでは不足。Homeの参加予定はオフ会詳細から「参加する」で登録するイベント参加。方式とイベント管理の範囲は [PRESENCE_AND_EVENTS.md](../PRESENCE_AND_EVENTS.md) で検討中。従来の未決定表記はこの合意を優先する。


## 背景の気配に関する最新の変更

画面を閉じて移動する間も移動先に気配が生まれることが必須。旧P03の背景処理除外は、追加された気配機能には適用しない。チェックインの3時間更新ルールを自動変更したものではない。気配の更新・再送で件数が増殖しないよう管理する。方式は [PRESENCE_AND_EVENTS.md](../PRESENCE_AND_EVENTS.md) の1滞在1気配案を検討する。イベント終了後の参加履歴はMVPに含めない。

## 背景の気配と3時間延長の連動（採用済み）

有効なチェックイン中に新しい観測で街内と確認でき、背景の気配更新が成功したときは、チェックインもサーバー受理時刻から3時間に延長する。古い観測・再送だけで延長せず、退出・失効後は復活させない。気配の寿命は10分のまま。位置の継続的な精密共有や移動履歴保存を採用したものではない。

## 気配・イベント範囲の追加合意

地図の気配は人数表示とする。5人以上のまとまりの分割配置を希望するが、地理的意味と分割仕様は確認中。背景で更新できない気配は10分で消す。入街前に背景共有を説明し、OFFで観測・更新停止と気配終了を行う（通信断時はサーバーへの反映が遅れる）。

イベントMVPは作成・編集・中止・参加・参加取消・定員・主催者の参加者一覧・重要変更連絡。承認制・待機列・当日受付・決済は含めない。参加者名は主催者と運営のみ、他の一般参加者には人数のみ。参加履歴は残さない方針で、終了後の物理削除時期は別途決定。

気配の表示分割は観測位置を変えず画面上の配置だけをずらす。6人までは一つ、7人では5＋2。元の人数を増やさず、別街区へ再配置しない。8人以上の一般則は詳細設計。
