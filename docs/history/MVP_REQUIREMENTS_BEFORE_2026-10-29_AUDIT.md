# yumegaoka — MVP要件定義書 v0.5（統合版）

更新：2026-10-28。会話の最新の合意を統合。過去案は [履歴](../history/MVP_REQUIREMENTS_BEFORE_CONSOLIDATION.md)、根拠は [DECISIONS.md](../DECISIONS.md) に保存。未決定事項を実装仕様に自動昇格させない。

## 1. 目的・段階

**街の人の気配を感じることができる、孤独な人間のための第六感。**

何も投稿しなくても人の存在を感じ、会話・合流・人間関係の維持を義務にしない。街に参加することと特定の相手を募集することを分ける。文化が現実に成立することが最終目的。

初期顧客は招待された通話界隈の人々、池袋でのオフ会を起点とする。iOS・Android向け。所有者が運営する。定性的な観察は仮説として扱い、追加インタビューを開発の先行条件にしない。

現在は基本設計と中心体験の技術検証。最新ユーザー依頼により隔離した検証コードの作成を開始。本製品全体の実装・未確定の基盤契約・公開はまだ行わない。

## 2. 参加・アカウント

- 招待登録済みの利用者のみ街の人数・地図・チャット・ピンを閲覧できる。招待案内画面は公開可能。
- 参加者も友人を招待でき、運営が状況を監督・無効化できる。
- サーバーにアカウント情報を保存。新端末から同じアカウントへログインして引き継ぐ。QR引き継ぎは不要。
- 復旧は登録メールを使う方向。メールOTP等の具体方式、旧端末失効、アカウント削除の詳細は未決定。
- アカウント設定で名前・本人アイコンを設定する。
- チャットは本人の名前・本人アイコン。地図の気配は流動的な街アイコン。画像素材・共有同意・割当の細部は未決定。

## 3. 街へのイン・アウト

- 新規チェックインは毎回NFC必須。終了・失効後に位置確認だけで再参加しない。
- 右上トグルのOFF→ON操作でNFC読み取り。サーバー登録成功後にON確定。キャンセル・失敗時はOFF。
- 有効期間は3時間。新しい街内観測による気配更新成功時はサーバー受理時刻から3時間へ延長する。前面復帰時にも位置を確認する。
- トークン一致だけでは足りず、滞在が有効・未退出・期限内であることと観測の鮮度・順序を検証する。
- OFFで手動退出。観測・更新を止め、気配と募集ピンも終了。退出後も街の閲覧・チャットは可能。
- 通信不能時は端末の退出意思を保持して延長を止め、再接続時に終了通知。サーバー反映は即時保証できず、各期限が上限となる。
- 更新不能なら気配は10分、チェックインは3時間で失効。位置不明は街外と断定しない。明確な街外では退出する。
- 遅延要求・再送・同時処理で人数を増殖させたり、終了済み滞在を復活させたりしない。複数端末による意図的な水増し対策はMVP対象外。

## 4. 街の気配（MVPの核）

- 入口だけでなく、街で移動した先にも気配が生まれる。投稿・募集操作は前提にしない。
- 画面を閉じてポケットに入れたままの移動にも対応する必要がある。背景観測の方式・許容遅延・電池消費は実機検証で選ぶ。
- 気配は10分で透明度が下がり消える。移動前の痕跡を積み上げず、同一滞在の最新1件を置換する方向。具体的なAPI・トークン方式は設計対象。
- 地図に人数を表示。6人までは一つ、7人は5＋2に表示分割する。観測位置を変えず周囲へ描画上だけずらす。8人以上の規則は未決定。
- 他利用者に名前や追跡用の安定した個人キーを公開しない方向。サーバー内で滞在・アカウントと対応付け得るため、完全匿名を保証しない。
- 正確な個人位置の常時公開や移動履歴の保存は目的としない。粗い区画への変換・集約は方式案であり、区画サイズは未確定。
- 入街前に背景で気配を共有することを説明する。停止はトグルOFF。
- 観測が途切れて気配が消えたことは現地0人の証拠ではない。架空の人を追加して賑わいを作らない。

## 5. 街・ステッカー・地図

- 初期設置は3か所以上。登録位置の凸包を街の外周とする。直線・地点不足等は検証し、範囲プレビュー後に確定する。
- 移設・交換・撤去に対応。タグの識別情報と最新設置位置を分け、旧タグ無効化・範囲の版管理を行う方向。
- 範囲変更だけで既存参加者を一斉退出させず、次回観測に最新範囲を適用する。
- NFCに前の利用者名を書かない。タグには識別情報を置く。運営端末で基本設定を書き込む。運営の書き込み端末はiPhone。
- 地図は当面MapLibre React Native。高品質な独自3D表現は「夢ヶ丘エリア」の文化的合意が生まれてから検討する。
- タグ機種・保護方式・地図タイル提供元・境界誤差の具体値は未決定。

## 6. 募集とオフ会

### 募集ピン

- 有効チェックイン中のみ作成。現在地を単発取得し、公開位置を確認して題名を付ける。
- 同時1件、20分で終了。手動終了・チェックアウト・滞在失効でも終了する。
- 題名は編集可。位置変更・継続は終了して再作成。編集で期限を延ばさず、終了したピンを復活させない。
- 公開後の位置は追従しない。気配とは別の、合流を求める意思表示。

### オフ会・イベント管理

- 未チェックインでも事前作成可能。題名・開始終了日時・場所が必須、説明は任意。
- 作成シート→地図で地点選択→入力を保持したシートへ戻る→公開。
- 開催前は開始まで、開催中は終了までを表示し、終了後マップから消す。時間表記の詳細は画面設計。
- ピンをタップすると詳細シート。「参加する」で参加登録し、Homeの参加予定へ表示。取消可能。
- 初期範囲：作成・編集・中止・参加・参加取消・定員・主催者の参加者一覧・重要変更連絡。
- 参加者名は主催者・運営のみ、一般参加者には人数のみ。本人は自分の状態を確認できる。
- 参加登録と街のチェックインは別。参加操作で街人数を増やさない。
- 過去の参加履歴はMVP不要。終了後の登録情報の物理削除期限は未決定。
- 承認制・待機列・当日受付・決済はMVP対象外。

## 7. チャット・画面・運営

- 街ローカルのテキストチャット。未チェックインでも閲覧・投稿可。名前・投稿日時・本文・本人アイコン。
- 名前付きの入街ログで友人の来訪を知れる。ログの保持期間は未決定。気配との時刻相関から本人が推測される可能性は残る。
- 遡る操作で過去30日分をロード。本人・運営による削除、通報、投稿制限、個人ブロックを扱う。運営は他人の本文を書き換えない。
- チャットを上へ広げて背景をぼかす。ジェスチャー・キーボード・閉じる動作は画面設計で確定。
- Homeは参加予定・募集中のピン一覧、Mapは街の気配・募集・オフ会・チャット、Settingsはアカウント関連。
- 現在地へ戻る操作と位置公開は別。最初に開くタブは未決定。
- 運営が招待監督、通報確認、投稿削除・一時停止・利用停止・解除、ステッカー登録・書き込み等を行う。同一アプリ内運営画面案は未確定。
- 権限検証・入力制限はサーバー側で行う。通報数だけで永久停止しない。

## 8. 承認済みの初期上限

| 項目 | 初期値 |
| --- | --- |
| 招待 | 1コード1回、7日有効、7日間に5件発行／参加者。運営が追加・停止可能 |
| チャット | 500文字、10秒に5件かつ1分に20件／人 |
| 履歴 | 1回50件、10秒に5回／アカウント |
| 募集 | 同時1件 |
| ピン作成 | 1分に3件／人、取消・再作成も含む |
| オフ会 | 同時3件、開始90日先まで、開催期間24時間以内 |
| 題名・説明 | 50文字・1,000文字 |
| 接続 | 1端末原則1本、1アカウント3本。再接続の一時重複は許容 |
| アイコン | 画像のみ2MB以内、縮小・再エンコード・メタデータ除去 |

## 9. 保存方針

- チャットは30日超で取得対象外、その後24時間以内に削除。
- 終了したピンの本文・座標は取得対象外とし、24時間以内に削除。通報対象の最小証拠は別管理。
- 終了滞在の再送判定用最小情報は24時間後に削除。削除済み滞在の要求を新規参加と扱わない。
- 気配の公開は10分。生座標・移動履歴を蓄積しない方向。内部の気配データ削除方法は設計対象。
- 通報証拠は運営限定、対応完了後30日で削除。未対応90日で整理。未対応の最長保持は未決定。
- セキュリティログ原則7日、運営操作記録90日。本文・位置・秘密トークンをログへ出さない。
- バックアップ原則7日を選定条件とし、実現可能性を確認。復元時は期限・削除・停止を再適用。
- 招待関係は有効アカウントの監督に使用。退会後、イベント登録終了後、アカウント削除時の扱いは詳細設計。

## 10. 技術検証と完了条件

製品の技術候補はReact Native＋TypeScript＋Expo開発ビルド、単一API＋PostgreSQLと管理型基盤。事業者・費用・ライブラリ等は未確定。

最初の技術検証は背景の位置観測をiPhone実機で調べる。検証専用のSwift/Core Locationアプリは製品技術選定を変更しない。Androidと実サーバー通信は別途検証する。

確認対象：画面ロック中の区画変化、10分を超える欠測、電池、権限拒否、省電力、通信断、手動退出、再送・逆順・失効後更新。観測頻度はOS制約があり、検証前に成立を保証しない。

P09の試験方向：池袋10〜20人、両OS。安定回線で同時接続50・毎秒5件10分の試験を想定し、サーバー受理→表示p95が1秒以内を目標とする。背景検知の遅延とは別指標。具体的な測定条件・配布・日程は今後決める。

公開前には招待・NFC・気配・ピン・イベント参加・チャット・退出・運営の一連の動作、権限分離、保存削除、両OS実機を確認する。現地で「何も投稿せず人の気配を感じる」「会話や合流を強制されない」を観察する。
