# 電信PIN — 採用仕様と画面契約

更新：2026-11-19。ユーザーの概念統合依頼、8項目の推奨案への基本同意、街外からの作成・1日3個・作成後の募集ON/OFF指定と添付Figmaを根拠とする。6点の追加推奨は同日のユーザー回答で承認済み。コードとローカルDB/APIの実装・対象検証済み。クラウド049/通知ワーカー配備とSimulatorの起動・作成導線を確認。作成シートの重なりは修正・Simulator確認済み。クラウド保存/他アカウント参加の画面一巡・実機確認は未完。iOSの標準部品への移行方針は[IOS_NATIVE_UI_PLAN](frontend-redesign/IOS_NATIVE_UI_PLAN.md)を優先。 R12/R13/R14/R16/R17/R19に対応。旧募集・オフ会を置換し、旧33タスクのDONE履歴は保持する。

## 採用済み

- 電信PINは地図上の地点に挿すステータスメッセージ。題名・説明・開催日時を分けず、必須本文のみ最大500文字。日時は本文で伝える。
- 招待登録済み会員が利用。街の外にいる、未入街、ゴースト中でも作成可能。配置先は対象の街の範囲内。ユーザーの居場所と配置可能範囲は別条件。
- 1人1日3個まで作成。同時3件の推奨案も維持。全街合計、日本時間0時で日次枠を更新。削除しても枠は返さない。作成成功のみ消費し、編集・失敗・同一操作再送は消費しない。
- 作成受理から24時間で全モード共通に失効し、地図・Home・参加中一覧から消える。編集、募集切替、参加、到着で期限を延長しない。退出・滞在失効・端末切替・ゴースト切替には連動させない。
- 作成者は本文編集、募集ON/OFF、手動削除が可能。削除は編集モード内にのみ置き、確認を挟む。終了済みPINを復活させない。
- 募集モードOFFはメッセージとして表示し、参加ボタンは出さない。ONは作成者以外に参加を提供する。後からON/OFF可能。「参加者がいればOFF不可」という前回推奨は最新指示で撤回。参加者がいる場合は確認後、全員の参加・到着を解除して通知する。本文は残り、再ONでは旧参加を復活させず再参加が必要。ホストの到着状態も解除する。
- 最大募集人数は募集モードと独立したON/OFF設定。上限OFFは無制限。上限ONでは参加予定＋現地にいる参加者の合計を数え、作成者は含めない。満員なら参加不可。定員を現在人数未満に下げられない。上限は1〜100人、ON時の初期値12。新規の募集・上限はともにOFF。上限だけ先に設定できる。
- 他人は「参加する」→参加予定→「現地につきました」→現地にいる、の順に移る。二重計上しない。到着は自己申告でGPS/NFC認証は不要。参加予定から取消、到着後は「離れる」で抜けられ、空席が戻る。
- 作成者は「主催者」の別枠に表示する。主催者の到着操作は設けず、現地にいる人・現地のアバター列・参加人数に含めない。入街状態でも自動掲載しない。
- 参加者の名前・本人プロフィール画像は、PINを閲覧できる会員全員に公開。現地にいる人と参加予定を分け、ホストを識別する。過去の参加履歴は作らない。
- 参加・到着は街への入街や気配人数を変更しない。ゴースト中でもPINの本人名・参加名は匿名化しない。
- 参加者がいる間の場所変更は不可、本文変更は可能。参加者なしでは地図から場所変更可能。公開地点は移動に追従しない。
- 参加中のPINの本文変更・削除を通知対象とし、通常の24時間失効は通知しない。既存のアプリ内通知＋Push経路を利用する。募集OFFでも解除対象者へ終了通知を送る。
- 自分のPIN作成/参加予定の成功も本人のアプリ内通知に記録する。同一操作の再送では重複せず、参加取消後も24時間以内の完了履歴は残す。「了解しました」で一覧から除く。本人の操作履歴にPushは送らない。本文は操作時のスナップショット、作者名/画像は現在プロフィール。
- Homeは全有効PINを「募集中」（ON）と「PIN」（OFF）に分類し、自分・参加中を識別する。予約は本文での予告のみで、予約日時・自動募集ONは設けない。
- 終了後は本文・座標を取得対象外とし、本文・座標・参加情報を終了から24時間以内に削除する既存保持方針を引き継ぐ。通報証拠は別権限・別期限。日次上限の最小記録は削除で上限回避を起こさない設計が必要。
- 認可・満員・日次上限・失効をサーバーで検査し、競合で超過させない。同じ操作の再送で二重作成・枠の二重消費・取消や終了後の復活を起こさない。

## Figmaから読む画面と遷移

参照原本：`docs/reference/denshin-pin/Group 740.png`（他人から見た状態）、`Group 741.png`（作成者）。画像内の名前・本文・人数・招待残数はサンプルで、実データや追加要件ではない。ヘッダーロゴ変更・招待仕様変更・予約実行機能まで採用したとは扱わない。

1. Home一覧→本文の行・位置確認からMap上の対象PINへ移動し、半画面詳細を開く。Homeの＋→Mapへ移動→作成シート。
2. Mapの通常PINは画像＋本文吹き出し。募集ONでは募集の立体オブジェクト、募集表示、本文、太めSF Roundedの名前、大きい現在人数と小さい上限/人、現地参加者のアバター列を組み合わせる。作者画像は両モードとも本人プロフィール画像。街pool画像は使わない。
3. PINタップ→地図を背面に残した半高の標準シート（iOS 26以降は実際のLiquid Glass材質）。閉じるボタンと取っ手があり、上へ広げると詳細・名簿を表示する。
4. 他人の募集OFF詳細は画像・本文・作者名。募集ON詳細は募集表示、人数、現地にいる人、参加予定、状態に応じた右下固定の操作を追加。
5. 「参加する」成功→チェック印の参加確定表示→詳細では「現地につきました」。確定表示はサーバー成功後のみ。失敗・満員では成功演出を出さない。閉じて地図/詳細へ戻れる。演出秒数は未固定。
6. 自分の詳細は「自分」、募集モードスイッチ、右下固定の編集ボタン。詳細には削除ボタンや通信確認ボタンを置かない。募集ON時は名簿も表示。スイッチから後でON/OFFできる。
7. ＋から作成、鉛筆から既存値入りの編集シート。本文、人数上限スイッチ、数値操作、募集スイッチ、「マップを挿入／変更する」、閉じる、保存チェックを配置。編集時は見出しを「電信PINを編集」にする。×は確認なしで未保存入力を破棄して閉じる。場所選択への移動は破棄と区別し、入力を保持する。
8. 場所選択→既存Mapで配置→完了→入力を保持した作成/編集へ戻る。保存までは公開内容を変更しない。初期値12は後続の明示承認により採用。数値操作は初めはコンパクトに表示し、タップ後にsheetと人数エリアをアニメーションで拡張。±ボタンで1〜100を設定し、増減で変わった桁だけを動かす。

取消・離脱・削除・満員・上限到達・送信中・失敗・失効の画面は添付にないが、採用機能を操作可能にする必要がある。未提示だから省略しない。本文500文字を地図で全表示せず、詳細で全文を読めるようにする（省略寸法は実装時調整）。

## 採用後の移行条件

他者の電信PINは募集ON/OFFとも、ヘッダーの閉じるボタン左側の「…」をタップして標準メニューから通報・ブロックを行う。iOSはSwiftUI MenuとLiquid Glassボタンを使う。投稿者画像の長押しと本文の操作行は置換し、実行前の確認と既存API/認可は維持する（2026-11-20最新ユーザー指示）。

詳細シートを拡大してもステータスメッセージの文字サイズは縮めない。「現地にいる人」「参加予定」は各対象者が1人以上いる場合だけ見出しと一覧を表示する。主催者の別枠表示は維持する。

Q-DP01〜06は承認済み。ブロックした作者のPINは両モードとも非表示。名簿の対象者も自分から非表示にするが人数には含める。本人の参加取消・離脱導線は確保する。旧募集・イベントの有効データを配備前に読み取り確認し、残っている場合は移行方針を相談、無断削除しない。

## 実装差分と受入条件

旧募集20分・滞在連動・当日pool画像、イベント日時/定員・限定名簿の実装は既存データ参照のため保持。新規作成・Home・電信PIN詳細は新仕様へ接続済み。検証範囲はTECH_VALIDATIONのDP01記録。

- R12：街外/未入街/ゴースト作成、配置範囲、日次3件・同時3件、再送、24時間失効、編集非延長、退出非連動。
- R13：モード切替、参加→到着→離脱、取消、満員同時参加、ホスト除外、定員引下げ拒否、編集/削除通知。
- R14：会員向け2リストと本人画像、非会員取得拒否、ホスト識別、終了後公開停止。
- R16/R17：投稿制限/利用停止/通報/ブロックの新PINへの接続、保持削除、古い要求からの非復活。ブロックは両モードで統一する。
- R19：添付の他人/自分、OFF/ON、半高/全高、作成/編集/配置/参加確定、失敗時の入力保持を確認。

DB/API/UIを実装し、ローカルDBと対象クライアント試験成功。049〜054はクラウド適用済み。実機外観・実Push・他アカウントとの画面一巡は未確認。検証事実はTECH_VALIDATIONに記録。新規必須作業としてDELIVERY_PLAN DP01で管理、工数未見積もり。旧33タスクの分母・DONE・固定残量は変えない。
