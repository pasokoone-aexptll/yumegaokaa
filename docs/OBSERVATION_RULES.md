# 観測の時計・区画・境界計算 v0.1

2026-10-29。FIRST_SLICE_CONTRACTのB01を具体化。対象R05〜R09/R11/R21、T05/T06/T09/T14。以下は内部設計の推奨方式。製品のSwift計算・背景接続を実装中。計算ベクトル等19 assertionを確認。本体の実機観測は未確認。G01（街外2回の最大間隔120秒）は承認済み。

## 1. 処理順

同じ端末の観測処理を直列化する：終了意思／権限確認→新しい測位か確認→時計・鮮度・精度確認→最新街範囲で内外判定→街外確認または区画計算→送信間隔判定→採番→送信。無効・保留で期限を延ばさない。サーバーは別途資格・session・visit期限・順序・版・申告精度・鮮度を検査する。

## 2. 時計補正

端末の設定時刻を滞在期限の正本にしない。サーバーUTCと、スリープ中にも進む単調時計を結合する。iOSではContinuousClock相当をネイティブ層で扱い、JSタイマーが背景で定刻実行されることに依存しない。

専用の時刻応答は返却直前のserver_timeを含む。単調時計の送信時刻m0・受信時刻m1を測り、往復時間r=m1−m0、受信時点のサーバー時刻推定をserver_time+r/2とする。これは通信経路の対称性を仮定する推定で、厳密な同期ではない。初期同期は最大3回、往復2秒以下の最小rの結果を採用。失敗時は観測更新を保留して再接続時に同期し、古い位置を延命しない。

受信後の推定時刻は基準推定＋単調経過時間。表示はスリープ後も経過時間を含める。新しい同期が古い推定より戻る場合、表示済みの期限切れ要素をその補正だけで復活させず、サーバーの新スナップショットでのみ再表示する。

同期は入街前・前面復帰・通信復旧・プロセス再起動時、背景では新観測の送信前に同期から15分を超えていれば行う。実行機会のない間にタイマーを起こすものではない。同期基準はプロセスを跨いで流用しない。

CLLocationのtimestampは端末の壁時計なので、callback時に取得した壁時計との差から観測の経過時間を求め、単調時計に対応付ける。壁時計の経過と単調経過に2秒超の不一致・負の観測年齢を検出した場合、その観測を捨て、同期と新測位をやり直す。過去のバッチを新しい時刻に付け替えない。再起動直後はキャッシュ済み測位を採用せず新規取得を待つ。実機でOSの時刻変更と測位timestampの挙動を検証する。

サーバー側は `observed_at > t + 5秒` を拒否。0〜5秒先はtへ丸め、未来による期限延長を防ぐ。120秒より古い観測は拒否。正規化後も前回観測より新しくなければ無反映。端末も同期の推定不確実性r/2を含め、古さの上限が120秒以下のものだけ送る案。これらは初期の内部許容値であり、時計同期の安全性・現地性を保証しない。

APIの観測時刻は補正済みUTCを送る。送信待ち・再送では元の時刻とseqを維持。30秒／約3分の間隔は単調時計で判定する。DBの判定時刻は既存設計どおりロック取得後。

## 3. 100m区画

Map描画の投影と観測の区画計算を分離する。池袋MVPはWGS84の緯度経度を横メルカトル投影でメートル座標へ変換する内部案：lat_0=36、lon_0=139.8333333333333、k_0=0.9999、false easting/northing=0、楕円体WGS84。原点・縮尺は日本の平面直角座標IX系を参考とするが、JGD測地系への正式変換をしたものやEPSGの公式IX系そのものとは呼ばない。

軸名はE（東）、N（北）で統一。緯度経度の引数順を各ライブラリの境界で明示する。投影定義をgrid_versionと一緒にサーバー設定へ保存し、不変にする。投影ライブラリはB02で選定し同じ試験ベクトルを端末・サーバーで使う。外部の変換APIへ利用者の生座標を送らない。

投影E,Nは1cmへ共通のround-half-away-from-zeroで量子化し、整数cmで計算する。`col=floor(E_cm/10000)`、`row=floor(N_cm/10000)`。負値もゼロ方向の切捨てではなくfloor。区画は半開区間、境界ちょうど100mなら次区画。cell_idは符号付き整数の `col:row`、街・grid版と組にする。処理系の丸め誤差はcm量子化境界で試験する。

100mは投影面上の長さであり地表距離に僅かな縮尺差がある。位置誤差50mと混同せず、MVPの街の粗い気配用途として使う。初期公開後の街境界変更ではgrid原点を動かさない。

### 20mの切替

初回は実際の計算区画を使う。継続中は最後に採用した区画の矩形を各方向20m拡張した領域にいる間、元区画を維持する。拡張境界ちょうどに達したら切替候補とする。東へ出る例では元区画[0,100)からE=119.99は維持、E=120.00で候補。斜めはEまたはNのどちらかが拡張限界へ達すれば候補となる。

複数区画を飛び越した場合は途中に気配を残さず、その観測が属する実際の区画へ直接切替。隣区画を一つずつ通過したことにしない。新しい区画の全辺から20m離れるまで待つ方式にはしないため、別軸の境界近くを歩き続けても移動を反映できる。

初回・旧気配失効後・プロセス再起動後は基準区画なしとして実区画を選ぶ。20m保持中でも送る区画が最新街範囲と交差しなくなった場合は実区画へ再初期化する。位置が街内かどうかは別の先行判定であり、区画保持を理由に街外をinsideへ変えない。

## 4. 街の内外

同じメートル座標上で、公開範囲の境界までの符号付き最短距離dを計算（内側正、外側負、境界0）。推定水平誤差aが有限・0以上50以下であることが前提。

- d > a：明確な街内。
- d < −a：明確な街外。
- それ以外：判定保留。境界接触も保留。

これで誤差円が境界を跨ぐ観測を保留できる。ただし誤差円は真位置の保証領域ではない。範囲に無断で余白を足さず、外周タグで気配が出ない場合がある合意を維持する。

明確な街外の最初の観測を端末メモリに記録し、その後も街外なら最初から30秒以上経過した新観測でoutsideを送る。30秒未満の街外観測で最初の時刻を毎回上書きしない。明確な街内、精度不足、内外不明、旧観測、範囲版変更、時計再同期で時間の連続性が失われた場合、再起動、OFFで確認状態をリセットする。

**G01・承認済み：2回の最大間隔を120秒とする。** 最初の街外から120秒を超えたら、次の街外を新しい1回目とする。10分前の街外と今の街外を「続けて確認」と扱わない。OS欠測が多いと自動退出が遅れ、既存3時間期限が働くが、街外確認中は更新・延長しない。観測は古さ120秒以内に加え、2回目の新しい時刻でサーバーへ送る。

30秒ちょうど／120秒ちょうどを許容。地点が同一である必要はなく、同じ最新範囲について連続した街外分類であることを確認する。生座標・2回分の位置をサーバーへ送らない。outside送信後の応答不明は同じseqのまま照会・再送する。

## 根拠

- [Apple Continuous Clock](https://developer.apple.com/documentation/swift/clock/continuous?changes=_3)：スリープ中も進む時計。これとサーバーUTCを結合するのは本プロジェクトの設計。
- [国土地理院・平面直角座標系](https://www.gsi.go.jp/LAW/heimencho.html)：IX系の適用地域・原点。
- [PROJ横メルカトル投影](https://proj.org/en/stable/operations/projections/tmerc.html)：投影パラメータ。使用ライブラリの選定や実機精度を確認済みとは扱わない。
