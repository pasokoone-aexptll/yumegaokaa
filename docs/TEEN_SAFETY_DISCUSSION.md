# 中高生を含めた公開の相談

2026-11-25。ユーザーは13〜17歳を含めたい意向。18歳以上限定案は採用しない。最低年齢・同意・具体的な安全対策は相談中で、登録画面や利用規約へ未適用。

## 年齢区分と参加条件を分ける

App Storeの年齢区分は質問票への実態に基づく回答から算定される。13歳も使ってほしいから回答を弱めない。利用規約の最低年齢が算定結果より高い場合は上書きが必要。[Appleの説明](https://developer.apple.com/help/app-store-connect/manage-app-information/set-an-app-age-rating/)

## 次に相談する具体案（いずれも未承認）

| 論点 | 提案 | 影響 |
| --- | --- | --- |
| 初回対象 | 13歳以上、日本のみ。13〜17歳を含める | 13歳未満への案内と年齢確認方法が必要。年齢自己申告だけで本人年齢を保証しない |
| 保護者 | 未成年の利用には保護者の同意を求める案を検討 | 規約文を置くだけか、記録／確認まで行うかを決める。国内法上の要件は別途確認し、一律にApple必須と断定しない |
| 本人写真 | 現行の必須仕様を維持するか、未成年には代替を認めるか相談 | 必須は承認済み仕様。勝手に解除しない。街poolの匿名風アイコンとチャット／PINの本人写真は別 |
| 合流 | 公開の街・PINで成人と未成年が同じ場へ参加できる現行仕様を点検 | 未成年だけ合流を止める／公開範囲を変えるなら製品判断。現行の100m区画は個人推測を完全には防がない |
| 通報・運営 | 未成年への勧誘、性的投稿、脅迫、個人情報公開等の優先対応を定める | 既存通報・ブロック・停止を使い、誰がいつ確認するか決める。未実施の24時間監視を約束しない |
| 投稿前確認 | テキスト・本人写真・pool画像・PINを対象に方式選定 | 禁止語だけで画像／文脈の判定を済ませない。外部APIは送信先・保存・料金の承認前に接続しない |

Appleの[UGC基準1.2](https://developer.apple.com/app-store/review/guidelines/#user-generated-content)に対応するフィルタ、通報対応、ブロック、連絡先の根拠を揃える。上の年齢別対策は製品提案であり、すべてがAppleの一律義務という意味ではない。

ユーザーに次回まとめて相談するのは、最低13歳という線引き、保護者同意の方法、本人写真と合流の扱い。今は年齢を収集するDB列や画面、未成年を拒否するロジックを追加しない。
