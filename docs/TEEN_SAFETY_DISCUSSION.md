# 13歳以上の利用と保護者同意の相談

2026-11-25。ユーザー決定：利用対象は13歳以上。プロフィール画像と現地合流は現仕様を維持。年齢条件は仕様として決定、年齢確認・保護者同意は未実装。保護者同意の方法は相談中。

## 用語と現仕様

プロフィール画像は利用者本人のプロフィール用画像であり、街の共有poolアイコンとは別。顔写真・顔出しを必須とする要件はない。以前の「顔出し必須を緩める」という提案は誤読のため撤回。画像登録必須の現仕様と現地合流の操作・公開範囲を変更しない。

App Storeの年齢区分は実際の機能を回答して算定される。利用対象13歳以上という決定だけで13+になるわけではない。[Appleの説明](https://developer.apple.com/help/app-store-connect/manage-app-information/set-an-app-age-rating/)

## 保護者同意の選択肢（未承認）

対象案は13〜17歳。18歳以上に保護者同意を要求しない。年齢確認方法は別途決める。

| 方式 | 登録の負担 | 確認できること・限界 |
| --- | --- | --- |
| 本人が「保護者の同意を得た」と申告 | チェック1つ | 本人の申告を記録できるが、保護者の意思を直接確認できない |
| 保護者が説明を読みメールの確認リンクで同意（推奨） | 初回に保護者の操作を待つ | メール所有者の操作と説明内容を記録。実際の親権者／後見人かまではメールだけで証明できない |
| 身分・続柄を確認するサービスや書類 | 負担・取扱情報・費用が増える | 確認を強化できるが、方式によって限界がある。初期案としては採用しない |

## 推奨案の操作（設計提案・未実装）

1. 登録時に13〜17歳と判定された場合、保護者に説明・同意用リンクを渡す。送信方法はメール招待か本人による共有かを選ぶ。保護者のアカウント作成は不要とする案。
2. 保護者本人が、サービス利用・プロフィール画像／チャット／PINの公開範囲・入街中の背景位置利用・成人を含む他者との現地合流を読む。同意の主体は親権者または未成年後見人であることを明記する。
3. 保護者のメールを確認し、対象アカウント・同意日時・説明／規約の版・確認方法を記録。保存期間と撤回窓口は実装前に決める。身分証・住所を当然に収集しない。
4. 確認完了後は通常の体験。毎回のログイン・入街・PIN参加では追加承認を要求しない。重要な取扱変更時の再同意と、撤回時の扱いは別途定義する。
5. 同意待ちの間は他者データの閲覧・公開・位置共有を開始しない案。既存の未成年アカウントへ適用する時期は別判断とする。

この案は低負担と記録の両立を狙う製品提案であり、メール確認だけで法的充足や審査合格を保証しない。親へ投稿履歴や現在地を共有する機能は含めない。年齢・未成年ラベルを他利用者へ公開しない。

## 法令の説明と製品提案の区別

個人情報保護委員会は、子どもが同意結果を判断できるかをデータ・事業の性質で個別判断すると説明する。13歳を一律に本人同意のみでよい境界としない。[個人情報保護委員会Q1-62](https://www.ppc.go.jp/all_faq_index/faq1-q1-62/)

未成年者の契約には原則として法定代理人の同意が必要という一般則がある。契約同意と個人情報の取扱いに必要な同意を分けて検討する。[千葉県の説明](https://www.pref.chiba.lg.jp/customer/soudanjirei/miseinen.html)

Appleが全ての13〜17歳利用アプリに保護者メール認証を一律要求するという説明ではない。UGCのフィルタ・通報・ブロック・対応体制の不足は、この同意だけで解消しない。
