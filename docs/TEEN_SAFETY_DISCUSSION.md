# 13歳以上の利用・保護者同意の採用方針

2026-11-25。ユーザーは「保護者の同意を得た」という本人申告のチェック方式を採用。登録で保護者の返信を待たせない。対象は13歳以上、プロフィール画像と現地合流は現仕様を維持する。方針確定／アプリ・DB実装は未完。

## 画像と現地合流

プロフィール画像は利用者本人のプロフィール用画像であり、街の共有poolアイコンとは別。顔写真・顔出しを必須とする要件はない。画像登録必須の現仕様と、現地合流の操作・公開範囲を維持する。年齢や未成年であることを他利用者へ公開する機能は追加しない。

## 採用する登録フロー

1. 登録時に13歳未満／13〜17歳／18歳以上を判定する。年齢の申告UI・保存粒度は別途確定する。生年月日や身分証を当然に収集しない。
2. 13歳未満は利用開始不可。13〜17歳だけに、初期OFFの「親権者などの保護者の同意を得た」というチェックを表示する。18歳以上には要求しない。
3. チェックの近くに、公開済みの利用規約とプライバシーポリシーへのリンク、プロフィール画像・投稿の公開、入街中の位置情報利用、成人を含む利用者との現地合流についての短い説明を置く。保護者へ共有できるURLを用意する。
4. 本人がチェックすると通常の登録を継続できる。保護者メールの入力、メール認証、別アカウント作成、保護者の返信待ちは設けない。同意未取得の場合はチェックせず、利用開始しない。
5. 申告をアカウントと結び付け、サーバー時刻・規約／説明文の版・申告方式を記録する。保存成功前に登録完了としない。通信再送で重複記録しない。既存の本人用メールOTPと招待QRは維持する。
6. 通常の再ログイン・入街・PIN参加では同じチェックを繰り返させない。重要な変更に伴う再申告と撤回の扱いは、提出前に決める。

文言案（公開版確定前）：

> 親権者などの保護者に利用規約とプライバシーポリシーを確認してもらい、利用の同意を得ています。

これは本人の申告を記録する方式。データ名・審査メモ・画面でも「保護者本人を確認済み」「保護者認証済み」と表現しない。チェックを初期ONにしたり、13〜17歳が年齢区分を切り替えた際の古いチェックをそのまま使ったりしない。

## 根拠と限界

[個人情報保護委員会Q1-62](https://www.ppc.go.jp/all_faq_index/faq1-q1-62/)は、子どもの同意能力を情報や事業の性質に応じて個別判断すると説明する。13歳を一律に本人同意のみでよい境界としない。[未成年者契約の一般則](https://www.pref.chiba.lg.jp/customer/soudanjirei/miseinen.html)と個人情報の同意を分けて確認する。

チェックは保護者の実際の同意を代替せず、本人の申告を示す。方式の採用を、法務確認済み・Apple了承済み・審査合格保証と扱わない。Appleが一律に保護者メール認証を要求するという意味でもない。[年齢区分の手順](https://developer.apple.com/help/app-store-connect/manage-app-information/set-an-app-age-rating/)
