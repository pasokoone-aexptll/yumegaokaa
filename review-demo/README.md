# 電信出口 App Review専用環境の準備

状態：構成準備。アカウント・環境は未作成。アプリの環境切替・パスワードログイン・NFC代替操作は未接続。このディレクトリを本番migrationや通常seedへ含めない。

## 確定した仕様

- 通常環境と別のSupabase Auth/DB/Storage、別gateway/worker。
- 審査専用環境だけメール＋パスワード（2026-11-25本人承認）。通常OTPは維持。
- パスワードはサーバーで生成・管理しApp Store Connectへ本人が入力。Git、公開設定、アプリへ埋め込まない。
- サンプルは架空の街・投稿・画像のみ。本番コピーは禁止。
- NFC/位置の代替操作はデモと明示。通報・ブロック・退会は共通の実処理。

## 作成するデータと確認順

| データ | 用途 | 準備条件 |
| --- | --- | --- |
| 審査員アカウントA | 通常操作一巡 | Auth管理APIで作成、期限・再ログインを確認 |
| 予備アカウントB | A退会後の再確認 | 別資格、同じ権限。削除したAを勝手に復元しない |
| 架空の投稿者2名 | 投稿・通報・ブロック確認 | メール送信・端末通知の宛先なし |
| 架空の街 | NFC代替と気配 | 本番の街・区画・画像のコピーなし |
| サンプルPIN/チャット | 作成・閲覧・参加・通報 | 安全な文章、実APIと同じ24時間/30日期限を維持 |
| 審査用招待 | 初期登録を確認 | 審査期間と再発行手順を確定 |

画像は提供可能な図形素材を使い、実在利用者の写真を使わない。年齢・規約への同意を本人に代わって偽造しない。初回ログイン時の申告を維持し、審査用アカウントでも同意前の制限を確認する。

操作順：ログイン→同意→Home/Map→デモ入街→気配更新→PIN作成/参加→チャット→通報/ブロック→退出→退会→予備でログイン。

## 配備前チェック

1. config.example.jsonを秘密情報なしの実設定へ置換。scripts/lib/review-demo-config.mjsで承認済みproject ref、本番との接続先分離、WSS、外部push無効を検査。
2. プロジェクトのAuth設定を確認。本番の認証設定を変更しない。
3. 共通migrationを適用。審査専用の代替入力は専用の配備物へ分離。
4. 通常とデモのセッション・native観測・画像キャッシュが交差しないことを確認。
5. 審査員の手順だけで、新規端末から主要操作が完了することを検証。
6. 審査中の休止・OTP依存・期限切れを確認。動画だけで代替したとしない。

設定validatorの成功は、サーバーの認可や実データ分離の確認を意味しない。
